# CivicFix AI — REST API Reference

Base URL (local dev): `http://localhost:8000`
Interactive docs (Swagger UI, auto-generated by FastAPI): `http://localhost:8000/docs`

All endpoints except `/api/auth/register` and `/api/auth/login` require a
`Authorization: Bearer <token>` header. Tokens are obtained from `/api/auth/login`.

## Auth

### `POST /api/auth/register`
Register a new citizen account.

```json
// Request
{ "name": "Jane Citizen", "email": "jane@example.com", "password": "secret123" }

// Response (201)
{ "id": 1, "name": "Jane Citizen", "email": "jane@example.com", "role": "citizen", "created_at": "..." }
```

### `POST /api/auth/login`
```json
// Request
{ "email": "jane@example.com", "password": "secret123" }

// Response (200)
{
  "access_token": "eyJ...",
  "token_type": "bearer",
  "user": { "id": 1, "name": "Jane Citizen", "email": "jane@example.com", "role": "citizen", "created_at": "..." }
}
```

## Users

### `GET /api/users/me`
Returns the authenticated user's profile.

## Complaints

### `POST /api/complaints`
Submit a new complaint. `multipart/form-data` (not JSON), because it
includes a file upload.

| Field | Type | Required | Notes |
|---|---|---|---|
| image | file | yes | JPEG/PNG/WebP, max size per `MAX_UPLOAD_SIZE_MB` |
| description | string | no | |
| latitude | float | no | -90 to 90 |
| longitude | float | no | -180 to 180 |
| category_hint | string | no | one of the 5 category enum values; used only if AI is uncertain |

Response: the full complaint object, including the AI prediction and
auto-assigned department, with status already advanced to `assigned` (or
`ai_analyzed` if no department mapping exists).

### `GET /api/complaints`
**Admin only.** Lists all complaints, newest first.

### `GET /api/complaints/my`
Lists the authenticated citizen's own complaints.

### `GET /api/complaints/{id}`
Full complaint detail including images, AI predictions, and status
history. Citizens may only view their own complaints (403 otherwise);
admins can view any.

### `PATCH /api/complaints/{id}/status`
**Admin only.** Advances the complaint's lifecycle status.

```json
{ "new_status": "in_progress" }
```

### `PATCH /api/complaints/{id}/severity`
**Admin only.** Manually overrides the AI/rule-derived severity.

```json
{ "severity": "critical" }
```

### `POST /api/complaints/{id}/images`
**Admin only.** Upload a resolution ("after") photo; automatically sets
status to `resolved`. `multipart/form-data` with an `image` field.

## Departments & Assignments

### `GET /api/departments`
Lists the five seeded departments.

### `POST /api/assignments`
**Admin only.** Manually (re)assign a complaint to a department.

```json
{ "complaint_id": 12, "department_id": 3 }
```

## Admin Dashboard

### `GET /api/admin/dashboard`
**Admin only.** Aggregate analytics:

```json
{
  "total_complaints": 42,
  "pending_complaints": 10,
  "in_progress_complaints": 5,
  "resolved_complaints": 27,
  "critical_complaints": 2,
  "category_distribution": { "garbage": 15, "road_damage": 10, "...": "..." },
  "department_performance": { "Sanitation": 15, "Roads and Infrastructure": 10 },
  "location_distribution": [
    { "latitude": 17.38, "longitude": 78.48, "category": "garbage", "severity": "low", "status": "resolved" }
  ]
}
```

## Status codes

| Code | Meaning |
|---|---|
| 200 | OK |
| 201 | Created |
| 400 | Bad request (validation failure, e.g. invalid GPS or unsupported image type) |
| 401 | Missing/invalid/expired token |
| 403 | Authenticated but not authorized (e.g. citizen viewing another citizen's complaint, or non-admin hitting an admin route) |
| 404 | Resource not found |

## Notes

These endpoint shapes match the proposed contracts in the project spec
(section 11) and are implemented as described, but should still be treated
as a v1 contract — request/response shapes may be refined as the frontend
and backend are developed together.
